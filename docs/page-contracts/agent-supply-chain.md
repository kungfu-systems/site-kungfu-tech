# Agent Supply Chain Contract

The Agent Supply Chain route connects the homepage's human handoff pain to an
Agent-native market mechanism before revealing the complete architecture.

Human and machine views are generated together at `/agent-supply-chain/` and
`/agent-supply-chain.json`. The product white-paper package owns the
cross-product narrative facts. This repository owns their reading progression,
composition, navigation, and rendering.

## Reading Progression

The route must establish the causal sequence in this order:

1. Kungfu earns one useful adoption by solving a concrete continuity problem.
2. The user keeps the Agent they already have.
3. Kungfu onboards that Agent through a versioned Brief.
4. Product-owned Work lets a later Agent inspect and continue the same facts
   instead of inheriting a chat transcript.
5. The Agent learns to recognize software that can declare capabilities,
   preserve responsibility, and show evidence.
6. That recognition can become a demand signal for builders.
7. Buildchain can help more products ship KFD-3 declarations and KFD-2
   evidence, allowing more Agent-native products to reach more Agents.

Only after the causal need is legible should the page introduce KFD-3, KFD-2,
Buildchain, Agent Hub, and the complete five-layer responsibilities and
evidence.

## Two Distribution Modes

Keep this distinction explicit:

- **Agent-assisted activation:** a product has already been chosen; the Agent
  helps the user understand and try it.
- **Agent-mediated distribution:** assessable product declarations and evidence
  let the Agent participate in product discovery and recommendation.

The Agent may recommend. A human or Hub still authorizes adoption.

## Ignition and Flywheel

Kungfu is the ignition source, not the permanent center of the loop. It must
earn the first adoption and show one Agent what better software feels like.
After that point, builders, Buildchain, KFD-conforming products, and Agents can
form a self-accelerating loop that does not require Kungfu in every transaction.

Self-accelerating does not mean self-starting. Every product still needs an
introduction and explicit authorization. The loop is a causal adoption thesis,
not proof of independent adoption, an existing multi-Hub market, or current
commercial demand.

## Kungfu Product Loop

The machine contract preserves the exact bounded loop:

1. The user keeps a familiar Agent.
2. The Agent learns the installed product through a versioned Brief.
3. It recommends durable Work only when bounded signals justify doing so.
4. It previews the minimal action.
5. It asks once for confirmation.
6. It leaves product-owned state and receipts for the next Agent.

The white-paper package remains authoritative for cross-product layer facts,
evidence coordinates, maturity classes, known limits, and adoption boundaries.
Do not restate those as locally invented site facts.
